# Deep Research 设计文档

## 概述

财报深度分析功能，通过 `/deep_research <query>` 斜杠命令触发。采用 Map-Reduce 架构，将用户问题按固定模板拆解为 3 个维度共 33 个子问题，逐子问题检索本地知识库，按维度聚合后 LLM 分析，最终汇总为结构化报告。

## 架构

```
用户输入 "/deep_research 华邦健康2025年财报分析"
              │
              ▼
    ┌─ 问题拆解 ──────────────────────┐
    │  固定 3 维度模板 → 33 个子问题   │
    └──────────┬──────────────────────┘
               │
    ┌─ Map 阶段（逐子问题） ──────────┐
    │  for each sub_question:         │
    │    rag.query(sub_question, k=3) │
    │  维度内去重合并检索结果          │
    └──────────┬──────────────────────┘
               │
    ┌─ Analyze 阶段（逐维度） ────────┐
    │  for each dimension:            │
    │    LLM(系统指令 + 检索结果)      │
    │    → 维度小结 (≤800字)          │
    └──────────┬──────────────────────┘
               │
    ┌─ Reduce 阶段 ──────────────────┐
    │  LLM(3份维度小结 + 用户问题)     │
    │  → 完整报告（一次性输出）        │
    └─────────────────────────────────┘
```

- 33 次 RAG 检索（每次 top_k=3）
- 3 次 LLM 维度分析 + 1 次 LLM 汇总 = 4 次 LLM 调用
- 完成后一次性输出

## 上下文管理

### Map 阶段

- 每个子问题 `rag.query(sub_question, top_k=3)`，取 3 条最相关结果
- 同维度内所有子问题的检索结果去重合并（基于 chunk ID）
- 去重后每个维度的检索结果约 15-25 条

### Analyze 阶段

每个维度的 LLM 调用 prompt 结构：

```
系统指令：你是金融分析师，根据提供的检索数据撰写 [维度名] 分析。要求：数据驱动，引用具体数字，指出同比变化和趋势。不超过 800 字。

检索数据：
[该维度去重后的全部检索结果]
```

不引用用户原始问题，保持维度分析的客观性。

### Reduce 阶段

汇总 LLM 调用 prompt 结构：

```
系统指令：你是资深金融分析师。根据以下三个维度的分析小结，结合用户的研究需求，生成完整的财报分析报告。报告需要连贯、有逻辑，并在最后给出综合评价和风险提示。

用户问题：[用户原始问题]

维度一：财务指标分析
[维度小结1]

维度二：资产负债分析
[维度小结2]

维度三：行业与业务分析
[维度小结3]
```

## 报告输出格式

```
═══════════════════════════════════════
  [公司名称] 深度财报分析报告
═══════════════════════════════════════

一、财务指标分析
  含盈利能力、费用率、ROE/EPS、现金流等

二、资产负债分析
  资产/负债结构、偿债能力、应收/存货/商誉

三、行业与业务分析
  业务构成、竞争格局、核心优势、风险因素

四、综合评价与风险提示

五、数据来源
  · 文档1名称
  · 文档2名称
═══════════════════════════════════════
```

数据来源只列出文档名，不列具体片段。

## 文件结构

```
deep_research/
├── __init__.py        # 公共接口：run(query)
├── template.py        # 固定维度模板定义（3维度33子问题）
├── pipeline.py        # Map-Reduce 流程编排
└── prompts.py         # Analyze 和 Reduce 阶段的系统提示词
```

在 `nanocode.py` 中，`_deep_research_loop(query)` 调用 `deep_research.run(query)`。

## Web Search 扩展点

`template.py` 中每个维度可额外添加 `web_search_sub_questions` 字段。`pipeline.py` 中检索阶段检查是否存在该字段，存在则调用 `web_search` 工具。当前版本该字段为空列表，不影响流程。

## 设计约束

- 仅本地 RAG 检索，Web Search 为预留扩展
- 检索使用现有 `rag.query()` 接口
- LLM 调用使用现有 `call_api()` 接口（OpenAI 兼容格式）
- 不使用 function calling / tool calling，Deep Research 的 LLM 调用是纯文本生成
- 报告完成后一次性输出到终端
